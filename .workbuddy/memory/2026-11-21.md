## v0.29.0 · 量词 / 反义词两个题型 + 单文件瘦到 3.97 MB

### 新题型

| 题型 | 数据 | 规模 | 年级 |
|---|---|---|---|
| 量词填空 `CLASSIFIER_FILL` | `refs/classifiers.json` | 255 条 | 1–5 |
| 写反义词 `ANTONYM` | `refs/antonyms.json` | 159 对（单字） | 1–4 |

- web：`web/js/gen/refs.js`；App：`RefGenerators.kt` + `RefBank` 的 `NounClassifier` / `AntonymPair`
- 三栏排版，题干压到十来个字：「填量词：一（　）书」「反义词：高——（　）」

### 这两个库为什么只能这么用（重要）

- `ref_antonym` 是**词典级的对义表**，不是小学反义词表。抽样直接看到：
  「春天—秋天」（春天没有反义词）、「渐渐—逐渐」（近义词，库错了）、「远处—远方」（同上）。
  双字对里这类错误两成以上 → **17,181 条双字对整批不要**，只留单字对。
- 单字对也要三筛：一字多反义（高→低/矮）、反向不唯一（亮→暗，可「暗」还有「明」）、
  同一对的正反两条（上→下 与 下→上）。筛完 335，再人工剔除 147。
- `ref_classifier` 同理：「一（首）花儿」（应「朵」）、「一（场）掩护」（掩护是动词）。
  约束「名词必须在教材词表里」能挡掉大半，其余靠 `CLASSIFIER_BLOCK` 黑名单（约 34 条）。
- 黑名单写法 `'牛|条'`，读时转 `frozenset` —— 顺序不用管，也不用担心 unicode 排序。

### 歇后语没做（说清楚为什么）

- 过完内容闸门还剩 4,268 条，但抽样 45 条有 2 处库自带错别字（「厚簿」、「摸到藉」）。
- zx 自己那 8,000 道歇后语题是**从这张表均匀随机抽的**（四~六年级各 2,000、100% 命中），
  不是人工精选，里面还有「婊子送客——假仁假义」。所以「教材认可」这条捷径不成立。
- 数据与 cleaner 都留着，`payloads` 里加一行就能接，等有精选清单。
- 成语库同理不扩：`ref_idiom` 四字且字表内 16,557 条，但混着「名我固当」这类古文片段
  和「额首称庆」（应为额手）这种错字，挖一个字只能靠蒙。

### 单文件瘦身：gzip 内联

- `tools/build-single.py`：>64 KB 的 JSON 走 `<script type="application/json-gz">`，
  `gzip.compress(9)` + base64，压完不如原文就退回明文体。
- `store.js` 的 `inlineJson` 改成 async，认 `json-gz` 类型后用
  `new Response(blob.stream().pipeThrough(new DecompressionStream('gzip'))).json()`。
  流式解，省掉「先解成字符串再 parse」那次整拷。
- 真题库 11.1 MB → 1.88 MB（gzip）→ 2.4 MB（base64），**单文件 14.82 → 3.97 MB**。
- 兼容性：Chrome 80+ / Safari 16.4+ / Firefox 113+；不支持的浏览器会在页面上直说。

### 坑（新增）

- **Kotlin 块注释可以嵌套**：注释里写 `refs/*.json` 时那个 `/*` 会再开一层，
  整个文件报 `Unclosed comment`。要么改成「refs 目录下的 JSON」，要么别写斜杠星号。
- **`write_poems` 非幂等**：`pre + block` 时 pre 末尾已含 8 格缩进，block 又带 8 格，
  每跑一次缩进 +8，跑几遍后整行都是空白。修法是 `pre.rstrip()` 再加 `'\n'`。
- 自检越加越长，`--virtual-time-budget=300000` 偶尔会在最后几条被截断（title 停在 42/49、
  正文还写着「运行中」）。加到 600000 就好，实际只跑 4 秒。
- e2e 页面**自己不跑 app.js 的 boot**，`DATA.refs` 是空的 —— 新用例要
  `if (!store.DATA.refs?.x?.length) await store.loadCoreData()`。

## v0.29.1：题库清洗（68,326 → 68,317）+ 大题深度排版

用户贴了一张印坏的卷子：「在横线里填上“＞”“＜”或“＝”。6　9　4+3　5　8+4　1220　12…」
—— 没有横线，两个数字黏成「1220」。要求两件事：**别再乱出题**、**大题能深度排版**。

### 那道题为什么长这样

原卷是**表格**：每格是「数 ○ 数」，提取成文本时表格线变空白、单元格变制表符/连续空格，
「12」和「20」两个相邻单元格就黏成「1220」。结构丢了就还原不回来 —— 这类只能剔，不能修。
从 68,326 道里定位到它的原始 stem：`在横线里填上…6 　 　 9\t4+3…`，确认不是答案错位。

### 清洗分三类（`tools/scrub_bank.py`，web 与 app 两份共用）

1. **能修的修**：`~\uline{~~}~` / `\\blank{}` → `＿＿＿`；双全角空格 → 单个填空位；
   `\t` → `＿＿＿`；句末标点后的长空白 → 换行；横排选项（圈号开头）→ 两个全角空格。
2. **修不干净的剔**：残留制表符、括号外连续空格、认不出的 LaTeX。
3. **结构必丢的剔**：填 ＞＜＝ 的表格题（判据见下）。

结果：改写题干 268、剔除 9（7 道比较位粘连 + 1 道填充表格 + 1 道 LaTeX）。脚本**幂等**，
`build-question-bank.py` / `import-zx-study.py` 收尾都调一次，以后重跑题库不会脏。

### 粘连题的判据（这次最绕的一段）

- **括号层数**：只看紧邻字符会误判 —— `逮捕(dǎi　　dài)` 的空白两头都是字母但在括号内，
  是「二选一」不是填空位。所以逐字符记 `paren_depths`，只在 depth==0 时认。
- **「填＞＜」比较位**：只用**单个**空格分隔的也会粘（`9+0○3+64+2○8-3`），
  「连续空白」判据拦不住。两条判据：①一格里有 ≥2 个比较位 ②比较位个数与答案符号个数对不上。
- 两个坑：「在○里填上」的 ○ 是**指示符**不是比较位（得先切掉说明句再数）；
  `(12分)` 有内容不算空括号（`SLOT_RE` 只认 `（）`）。

### 大题深度排版（电脑端独占，与「编辑排版」同一权限）

`section.layout = { cols, cellH, colGap, rowGap, blank }`，缺省 null = 跟随全卷。
面板五个旋钮：每行几道 / 每格高 / 列间距 / 题间距 / 每题留白 + 「恢复全卷版式」。

- **列数优先级**：`layout.cols` > 整卷 `forceColumns` 滑杆 > 自动试排 `fillColumns`。
- **`columnsThatFit`**：门槛用 `max(widths) * 0.85`。死守用户点的 4 列会让某一道长题折行、
  把整列撑高（坐标数据验证过：改 3 列后每题 18.5pt、0 折行）。差一点的题**单独**用
  `fitSize` 缩到 85% 下限，面板里直说「实际排 N 列」。
- **`minHeight`**：`measure()` 返回 `Math.max(内容高, minHeight)`，只撑不压。
- `FlowLayout.applyColumns` → `applyGeometry(columns, columnGap)`，列间距可按段切换，
  只在整宽块（大题标题）处换。

### 坑（新增）

- **清洗脚本必须幂等**：输出分隔符要与后续规则的判据一致 —— 选项用两个全角空格分隔，
  就不能让 `fix_space_runs` 把它们当填空位。顺序是 `fix_space_runs` 在前、`fix_tabs` 在后。
  第一版顺序反了，第二遍跑又改 16 道。
- **`~ ~ ~ ~` 是 docx 缩进不是填空位**：不当心会把「成绩」和「王教官说」中间塞进 `＿＿＿`。
  `TILDE_RUN` 必须先于单点替换。
- `（\n）` 会把空括号印成两行 —— 括号内一律换两个全角空格，不换行。
- **滑杆拖动会中断**：每次改动都 `render()` 重建面板，输入元素被替换掉。改
  `patch(key, value, rerender)`，滑杆传 false。
- **「每行几道」不能用 chip**：编辑面板窄，chip 会换行。改 `stepper`，单位用
  `edit-hint tight`（`flex: 0 0 auto`）紧贴。
- 折行不能劈下划线组：行尾落在 `＿＿＿` 中间时整组退到下一行（`measure.js` 与
  `TextPainter.kt` 同一条规则）。

### 验收

单文件 `file://` 实测「真题库（68317 道）」；自检 50/50（新增第 50 条盯大题排版：
4 列 0 折行 / 42pt 等高 / 留白撑高 / 恢复清空 layout）；release APK 4,104,661 B。
提交 `cc3529e`（题库清洗）、`a907ee5`（大题深度排版），已推 main。

## v0.29.2：全项目体检（四个隐藏 bug + 题库再收 7 道）

用户说「检查一下代码和项目的所有功能是不是都是正常的」。逐项跑下来，四个真 bug：

### ① 横排选项题被闸门误杀（最要紧）

v0.29.1 的清洗脚本把横排选项统一改写成「①…　　②…」（两个全角空格），
而 `isBadExam` 把「括号外连续空格」一律判成表格压扁残渣 → **21 道洗干净的题被永久拦死**。
修法：闸门放行「空白后面紧跟圈号 ①-⑳」。两端同步（`CIRCLED_RE` / `CIRCLED`）。

**教训**：清洗器的输出形态必须与闸门判据一起改。只改一边 = 白洗。

### ② 加一道大题后新题没有热区

`appendSection` 加完 5 道，纸面印出来了，但那 5 道**双击改不了、点也选不中** ——
新题没有 `uid`，而热区是按 uid 对到题上的。修法：加题后调 `ensureUids(paper)`。

### ③ `ensureUids` 会撞号

老实现「缺 uid 就从 q1 重新发号」，一旦部分题已有 uid（加题、开旧卷库）就把前面的题覆盖掉，
表现是「点 A 题弹出 B 题」。新实现先收集已占号再跳过，幂等。

### ④ Esc 关不掉弹窗

只有 ✕ 和「取消」两条出路。补 document 级 keydown，Esc 只关窗、不触发底部按钮 onClick。

### ⑤ 题库 68,317 → 68,310

又扫出 7 道结构真丢了的残题，写进 `GLUED_TABLE` 逐条点名：
6 道表格压扁（「糖葫芦的串数 / 2 / 4 / 5 / 6山楂的个数」「5吨＝＿＿＿kg2日＝＿＿＿时」
「A 包装(每盒1个) / 5元B包装(每盒3个)」这类两个单元格黏成一句）、
1 道答案错位（问「至少要付几张」答案却是「5元 10元」）、
1 道空位丢失（引号里只剩 `“ ， 。”`）。

**为什么不写通用正则**：表格线丢后「单元格黏连」与「竖排选项」文本上长得一样
（`…填几张?3张\n4张\n5张` 是竖排选项，可读），一条抓得住前者的正则必然误伤后者整批。

### ⑥ 构建不可复现

`gzip.compress(raw, 9)` 默认把**构建时刻**写进 gzip 头 → 同源码每次字节不同，
git 里每次多一个 4 MB 假 diff。改 `mtime=0`，连跑两次 MD5 一致。

### 体检方法与结论（下次照这个跑）

- 数据一致性：web/data 与 app assets 逐文件 MD5，10 个文件全一致
- 清洗幂等：内存里重跑 `scrub_doc`，改写 0 / 剔除 0
- 题库完整性：`tools/rebuild.py --audit`（68,310 道、零缺答案、两个科学年级告警属数据覆盖不足）
- 自检：**50/50**（puppeteer 等 60 秒；`--virtual-time-budget` 会快进 setTimeout，
  导致 waitFor 提前超时，截图出的 42/50 是**假象**，别被它骗）
- 交互实测：puppeteer-core + 系统 Chrome（`/tmp/pmtest`，不污染项目依赖）。
  **坑**：CDP 注入的鼠标 `clickCount:2` **不会合成 dblclick 事件**，测双击要在元素上
  `dispatchEvent(new MouseEvent('dblclick'))`；`page.mouse.click` 的单击是有效的。
- 三档视口 1440 / 820 / 390 逐页截图，查 `documentElement.scrollWidth > clientWidth` 判横向溢出
- 导出 PDF 用 CDP `Page.setDownloadBehavior` 拦到临时目录，看文件大小（527 KB）
