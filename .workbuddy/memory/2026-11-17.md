## 关键技术决策（后续维护看这里）

1. **纯静态、零构建、零依赖**：ES module 直接跑，`python3 -m http.server` 即用；**必须走 http**，`file://` 读不到 `data/*.json`。
2. **单位全用 pt**：CSS pt = PDF pt = 1/72 英寸，A4 = 595×842pt，打印不换算。打印对话框必须选「实际大小 / 100%」。
3. **排版产出绘制原语**（`{k:'text'|'line'|'rect'|'fig'}`），DOM 只做绝对定位摆放 —— 排版与渲染解耦，翻页由引擎定，不交给浏览器流式排版。
4. **数据从 Kotlin 导**：`tools/dump/Dump.kt` 编译命令（踩坑后的可用版本）：
   ```bash
   JH=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
   GL=~/.gradle/wrapper/dists/gradle-8.9-bin/78qddjpeqn5v6yec3xb8kv9ca/gradle-8.9/lib
   $JH/bin/java -cp "$GL/*" org.jetbrains.kotlin.cli.jvm.K2JVMCompiler -no-stdlib -cp $GL/kotlin-stdlib-1.9.23.jar \
     -d /tmp/dumpout -nowarn Models.kt CustomSheet.kt ... Dump.kt
   ```
   坑：troves 等依赖必须在同一 `-cp` 路径里；`CustomSheet.kt` / `PaperDocument.kt` / `PaperGrid.kt` 要一起编。

### 8) 单文件版 HTML（23:30~23:55）

用户原话：「我要的就是单页面html可以直接访问」。之前网页版是 24 个 ES 模块 + 10 个 JSON，必须 `python3 -m http.server 8778` 才能开；双击 `web/index.html` 只会看到「数据没加载上」（`file://` 下浏览器拦 ES module 的跨源加载和 `fetch`）。

**做法（没有第二份实现，还是同一套源码）**
1. `web/js/data/store.js` 的 `getJson()` 前面加 `inlineJson()`：按路径找 `<script type="application/json" data-pm="data/xxx.json">`，`JSON.parse` 一次就进 Map 缓存，找不到才 `fetch`。开发版（http）完全不受影响。
2. 新建 `tools/build-single.py`：npx esbuild 把 `js/app.js` 打成 IIFE（24 模块 → 136 KB 压缩后）→ 读 `web/index.html` 做替换（`<link>` → `<style>`、入口 `<script type="module">` → 内联数据 + 内联 bundle）→ 输出根目录 `试卷工坊.html`（3.25 MB）。
3. `boot()` 的失败文案按 `location.protocol` 分岔：`file://` 就指去单文件版，http 才是真出错。

**两个设计取舍**
- 数据用 `type="application/json"` 而不是 `window.__DATA__ = {...}`：3 MB 对象字面量一打开就要完整解析，纯文本浏览器只当字符串放着（课本页的五科懒加载依然成立）。
- JSON 里的 `<` 全转 `\u003c`：题库里有「A. <」这类选项，不转会把 `</script>` 提前闭合。

**验证**
- 单文件版注入式黑盒自检（file:// 真跑）：13/13 —— 10 份数据解析、启动出卷 2 页、预览 2 张纸面（首页 439 字）、导出 PDF 250 KB 且 `%PDF-1.4`、localStorage 可写、课本页 905 字、零 JS 报错。
- 截图：1440 宽下左侧导航 + 两页并排 71% · 2 栏，与 http 版完全一致；1500 那次截图只有 756px 宽 —— `--force-device-scale-factor=1` 加上去之后 `--window-size` 就失效了，去掉才正常，别再用这个参数。
- 开发版 `e2e.html` 回归 **26/26** 全绿（store.js 改动没破坏 http 路径）。

**后续**：改 `web/` 任何源码后都要重跑 `python3 tools/build-single.py`，否则单文件版还是旧的。

### 9) 拼音重复 + 编辑排版重做（23:50~01:20）

用户四件事：① 31 与 34 是同一个词（tóng xué）；② 编辑排版要能点哪儿改哪儿；③ **最主要别破坏原来的布局**；④ 每大题能单独定 1/2/3 栏；⑤ 编辑时好看点；⑥ 图 2 那行题数想并到标题里、顶部底部能压，好多印内容。

**① 拼音重复**
- 根因：去重键是 `stableHash(stem)`，同一素材换措辞 hash 就变了（「拼音 tóng xué，对应的词语是」vs「根据拼音写出词语：tóng xué」），所以框架根本没拦。
- 改法：生成器自己按素材记账。web 加 `nextFreshWord(ctx, pool, keyOf)`（`ctx.usedKeys`）；Kotlin 在 `GenContext` 加 `usedMaterials` + `freshWord()`，素材光时抛 `NoFreshMaterialException` 让框架跳过（宁可少出几道）。
- 顺带发现同病的：生字 / 补词题干只露**首字**（「给「太」注音」），按词去重不够，改按首字；英语四个问法也按单词去重。
- 副作用：一年级词池只有 8 个词，去重后 30 道只能出 8 道。两端**末尾追加** 22 个一年级词 + 11 个二年级词（拼音逐个核过），现在一年级 30 个词能出满 30 道不重复。

**②③ 原地编辑 + 改字不洗牌**
- `renderer.js` 的 hits 增加 `no / size / lines / itemGap / figure`（重画原件），并新增导出 `repaintQuestion(pages, qid, stem)`：删掉该题旧节点 → 按 5% 档缩字号找到能塞回原 slot 的最大字号 → 原 x/y 重画。
- `paper.js`：primitive 加 `data-q`，新增 `inlineEditor()` —— 盖在该题 slot 上的白底浮层，字号行高跟纸面一致（pt 单位，随 zoom 缩放），输入时 `grow()` 自撑高，`max-height` 到纸底为止。
- 高度试了三版：锁死原格子（只剩一行，看不见自己写的字）→ 长到下一题之前（题目排得紧，没留白可用）→ **浮起卡片 + max-height 封顶**，允许临时遮挡。
- `app.js`：`commitInlineEdit` 只 repaint 不重排；`relayout()` 专给「改卷面结构」（标题一行 / 页脚）用 —— 这类必须真重排，否则编辑模式下 paper 还是冻结的旧版（这个坑第一次就踩了：标题合成一行后首题 y 一点没变）。
