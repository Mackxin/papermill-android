# v0.10.2 按钮高度 46dp → 40dp

## 起因
用户 11-14 提「系统打印、保存、分享 这三个按钮的框，不要那么高，你看一下排版」。
量出来：三个按钮宽 138 / 106 / 106dp，高 46dp —— 窄而厚，像三块立着的砖；
底部操作条 54dp 也跟着厚。

## 改法
- `PaperDimens` 新增 `ActionBtnH = 40.dp`，`ActionBarH` 54 → 48dp
- `PrimaryButton` / `SecondaryButton` 的高度改用它（全 App 唯一定义处，改两行覆盖所有页面）
- `StickyBar` 上下留白 5dp → 4dp

## 踩坑
1. **uiautomator 的 bounds 量不出按钮真实高度**：改前改后都报 126px，
   因为 Compose 的 `clickable` 会把语义可点击区扩到 48dp 最小触摸区。
   要量真实高度必须走像素：精确匹配填充色（次按钮 #F2F3F9、主按钮 B-R>30），
   实测 105px = 40.0dp 才算数。
2. **次按钮的 #F2F3F9 和操作条底 #F5F6FB 只差 3/3/2**，容差 ±3 会把整条 bar 算进去，
   必须精确相等匹配。
3. `sed -i ''` 在 macOS 上带多表达式要用 `-e`，直接拼两个 `s///` 会当成文件名报错。

## 实测
按钮着色区 105px = 40.0dp（420dpi）；首页 / 自由组合 / 预览三页复查，
文字居中无裁切，与 dock 间距协调。APK 11,341,783 字节。

# v0.11.0 新增「科学」科目（1–6 年级 / 216 道自编题）

## 需求
用户：「可以增加一门科学的，每个年级都可以加，根据简易难度分类」+
「科学的题目可以搜索网络上的一些，要求都是小学生可以做的懂得」。
落地口径：题目**全部按小学科学课标知识点自编**（版权边界一致），不做网络抓题；
难度按 1 基础 / 2 标准 / 3 提高三档标注，按年级就近取题。

## 结构
- `domain/content/ScienceBank.kt`：加载 `assets/science/bank.json`，`draw()` 按难度「就近取」
- `domain/generate/ScienceGenerators.kt`：选择 / 判断 / 填空三型
- `tools/build_science_bank.py`：题库生成 + 校验（可重复运行），输出 216 题 / 38.3 KB
- `Models.kt`：`Subject.SCIENCE`（grade in 1..6）+ 三个 `QuestionType`
- `PaperComposer`：单科科学默认 8/10/8；综合卷勾了科学给一道科学大题
- `AppState`：每日一练排除科学；`poolDrained` 状态；补满提示分三段
- `DebugSheetDump`：三型纳入体检，选择题答案机器核对

## 踩坑（三条都是「整块内容消失」级别）
1. **JSON 短键 / 长键不匹配 → 选择题整批丢弃**
   生成脚本输出 `g/d/k/q/o/a/e`，加载器读 `grade/difficulty/kind/stem/options/answer/explain`，
   选项读成空数组 → 选择题洗牌时 `correctIdx` 越界整批 return null。
   现象：「科学选择 要 12 题 / 出 0 题」，卷子上一个大题凭空消失。
   修：两边统一长键（216 条只多 2 KB，完全不必省）。**生成端和读取端必须用同一份字段名，
   中间没有 schema 校验，错了不报错只丢数据 —— 这是最阴的一类 bug。**
2. **历史避让把 12 道的小题库整池挡光 → 大题消失（30 题印成 22 题）**
   `ctx.blocked` 装着最近几张卷的题干 hash。数学题库大（几百道）无所谓，
   科学每级每型只有 12 道，第二张同年级卷直接被挡光。
   修：`GenContext.allowReuse`——正常出卷 true（宁可重印两道旧题也要填满），
   补满探针 false（要的是真正的新题）。生成器里「前两轮不绕过、第 2 轮起才绕过」。
   **教训：题库规模会改变机制的正确性。同一个避让逻辑在 500 道池子里是优化，
   在 12 道池子里是灾难。**
3. **去重口径不统一 → 同一题印两遍（34 题贴成 46 题）**
   全 App 其他地方用**渲染后题干** hash 避让，科学生成器最初用**原题干** hash，
   补题探针认不出旧题，把已有题当新题又追加一遍。
   修：纸内去重用原题干 hash、历史避让用渲染后题干 hash，并同时记进 blocked。
   **教训：hash 去重的「口径」必须全 App 统一，否则等于两套字典互不相认。**

## 其他细节
- 判断题必须 √ / × 各半。随机抽 10 道很容易「八个 √ 两个 ×」，学生靠蒙就过。
- 默认配比曾想开 30 题，但每型只有 12 道，会印出「标题 30 题实际 12 题」的卷子 → 改 8/10/8。
- 题库抽干 ≠ 版面没排满。两种情况必须分开说，否则用户一直点「补满这一页」永远没反应。
  `poolDrained = plan.drained || (plan.extra > 0 && lastContentFillPercent < 84)`
  （只靠 `plan.drained` 不够：`fillToPage` 可能因页数到顶提前 break，走不到 noProgress）。

## 实测基线
- 六科并排显示正确（三年级时物理 / 化学置灰）；科学 1–6 年级均可选
- 选择题答案核对 24/24 OK（答案字母指向的选项文字 == 源题正确选项）
- 三年级科学单科卷 34 题 / 3 页，连出两张都是 34 题（题库上限，末页 39% 是抽干不是排版问题）
- 点「补满这一页」→ 提示「这一年级的题已经全部用上了（共 34 道）」
- 数学卷回归 52 题 / 2 页，未受影响
- APK 11,360,709 字节（versionCode 17 / versionName 0.11.0），内含 assets/science/bank.json 39,173 字节

## README
题型数 46 → 49（三处）；内置内容表加「小学科学 216 道」；功能表加 v0.11.0 科学行；
版权段加 v0.11.0 自编说明；版本表加 v0.11.0 / v0.10.2 / v0.10.1 三行。
第 87 行原写「默认一张卷 34 题（12+10+12）」，与实际配比 8/10/8 不符，已校正为
「默认配比 26 题，满页机制补到题库见底（三年级实测 34 题）」。

# v0.11.1 配平科学判断题（每级 6 真 6 假）

## 起因
v0.11.0 发版后核对包内题库，发现判断题池是 8–10 √ 对 2–4 ×（一年级 8/4、四年级 10/2）。
而 `ScienceBank.draw()` 是「真取 count-count/2、假取 count/2，不够就用剩下的补」——
假的不够时补进来的仍是「真」，10 道卷子实际印成 6√4×。
学生全蒙 √ 拿 60%，判断题防「靠蒙过关」的目的被抵消；README 和发布说明写的「各半」也不成立。

**教训：写了「强制对半」不等于真的对半。配比逻辑再对，池子里没料也是空转。
要验的是「卷面上印出来的比例」，不是「代码里的取法」。**

## 改法
把 17 道「真」题改写成误解型「假」题（保留/填充解析），每级变成 6 真 6 假：
- 一年级 2 道：蜗牛背壳爬得慢所以不是动物 / 水和木块都有固定形状
- 二年级 2 道：木头棉花是人造材料 / 用手摸就知道所有事情
- 三年级 2 道：气温指风力 / 根只固定不吸水
- 四年级 4 道：声音只能在空中传播 / 心脏是呼吸器官 / 受力就一定运动 / 食物在嘴里不消化
- 五年级 4 道：光在任何情况都沿直线 / 热从冷传到热 / 动物是生产者 / 只有镜子能反光
- 六年级 3 道：只有磁铁能产生磁性 / 能量用掉就消失 / 只有动物有细胞

改写原则：假题要写成**孩子真会犯的误解**（不是一眼假的错句），并在解析里点明正确结论。

## 加保险
`tools/build_science_bank.py` 增加硬校验：任一年级判断题不是 6/6 就 `sys.exit(1)`。
这类「不报错只降质」的偏差最难发现，必须靠断言挡住。

## 实测（模拟器 emulator-5554，release 包真机路径）
- 首页显示「49 种题型」✓；三年级纯科学卷「共 26 题」（= 默认 8/10/8）
- 出卷后自动补满到 34 题 / 3 页，末页 39%，题库上限提示正常
- 题目清单逐屏采集 34 题：选择 12 + 判断 10 + 填空 12
- 判断题答案 **√ 5 / × 5**
- 10 道判断题逐条与题库比对 **10/10 一致**
- 18 组「年级 × 难度」模拟抽题：10 题全 5/5、12 题全 6/6
- APK 11,361,401 字节（versionCode 18 / versionName 0.11.1），包内 bank.json 40.1 KB

## 采坑
1. **逐屏 uiautomator 采集会把「答案行」串到别的题上**：屏幕切割时上一题的 `答案：` 落在
   下一题题干之后，导致 #7「水沸腾温度」被错记成「（A）固态」。用截图复核才发现是采集问题，
   App 本身答案正确（#7 实为（B）100℃）。**跨屏抓文本一定要用坐标或截图交叉验证。**
2. 预览页 A4 是位图，uiautomator 取不到卷面文字；要核对卷面内容走「题目清单」页签。
3. `gh release create <tag> <apk>` 带附件一步到位会被 SIGTERM 中断（两次都 137），
   而且留下的是 **draft** 状态、资产链接是 untagged。可靠做法：先建空 release（秒回），
   再 `gh release upload`（可后台跑），最后确认 `isDraft=false`。

# v0.11.2 排版三修：竖式三栏 / 去重复指令 / 答案页撑满

## 用户反馈（三条一起提的）
1. 答案页只占上半张纸，空白太多
2. 试卷里重复的文字太多（「重排字母组成单词：」一页十几遍）
3. 竖式计算明明可以并排，却一题占一整行 → 「可以分成三列」

原话还点了一句方法论：「**很多地方你要学会优化排版，不要一味认为就是这样，可以自由组合的**」。
—— 这句是这次改动的核心：排版参数应当是「算出来的」，不是「定死的」。

## 病根
- **`QuestionType.columns` 从来没生效过**：排版侧只把 `<= 1` 当成「单栏标记」，
  实际栏数一律 `spec.columns`（全局 2）；而 `answerLines > 0` 又强制整宽。
  于是竖式声明 1 栏 → 永远单栏，题型自己的推荐栏数是死数据。
- **做题指令拼在每道题的题干里**（MathGenerators / EnglishWorksheetGenerators），
  这是生成端的写法问题，排版端再聪明也救不了。
- **答案页栏数只有 2 或 4 两档**（`maxAnswerLen > 20 ? 2 : 4`），选完就排，剩余高度不管。

## 改法
1. 栏数 = `max(题型推荐栏数, 用户全局栏数)`；竖式 `columns=3, answerLines=3`。
   同时删掉「有答题线就强制整宽」，只保留 `columns <= 1` 作单栏标记。
2. `QuestionType.instruction` + `GeneratedSection.instruction` + `PaperSection.instruction`
   → 渲染时 `SectionHeaderBlock` 后面跟一个 `NoteBlock`（改成支持折行）。
   生成端去掉每题前缀；`PaperComposer.hoistInstruction()` 兜底：
   同一大题题干的最长公共前缀若以冒号结尾、含 ≥3 个字、抽完不留空壳，就提为说明。
3. 答案页自适应：试排 2..6 栏，**取能一页装下的最少栏数**（栏越宽越好读），
   再把剩余高度摊到 `QuestionBlock.itemGap`（上限 26pt）撑满整页。
   注意 `rows` 要用向上取整，否则末行不满时行距算错。

## 顺带修掉的四个（都是体检时看出来的）
- **两位数题号粘题干**：题号槽位固定 20pt，「10.」正好 20.4pt 溢出 → 印成「10.5047」。
  改成按实际字宽量 + 3pt；`measure/paint` 必须用同一个缓存值，否则折行与绘制错位。
- **答题横线太密**：间距 = 1 行高（≈16pt ≈ 5.6mm），四位数竖式写不进去 → 改 1.55 倍。
- **孤行标题**：`Block.keepWithNext` + `FlowLayout.keepChainHeight()`，
  标题 / 说明连同后面第一道题必须同页（链条式，不是只看下一块）。
- **补题重复折算答题线高度**：`suggestedExtra` 只按栏数算、`fillToPage` 又除 `1+answerLines`，
  竖式卷每轮只补 1/4 量 → 末页永远差一截，还误报「题库不够了」。
  改成高度统一在 `suggestedExtra` 里算（`TYPICAL_QUESTION_H + answerLines × 24.8`），
  调用处不再除。顺带把「预计 N 页」也改成按题型高度折算（原来竖式卷多报一页）。

## 实测（DebugSheetDump 新增 3 个固定样本，量页尾空白 pt）
| 样本 | 改前 | 改后 |
|---|---|---|
| 答案页 34 题 | 2 栏半页空 | 2 栏撑满（5pt） |
| 答案页 32 题 | 2 栏只占上半 | 5pt |
| 答案页 15 题 | 559 | 295 |
| 语文卷长答案页 | 196 | 64 |
| 竖式 16 题真机 | 一题一行 | 3 栏 / 2 页 / 末页 96% |

真机（release 包）端到端：自由组合 → 竖式计算 +10 → 自动补满加到 16 题 → 生成 → 2 页 96%。

## 教训
- **参数写在枚举里 ≠ 参数生效**。`columns` 这种字段很容易被下游「只当布尔用」，
  改排版前先确认它到底有没有被读，否则会在错误的地方调参数。
- **重复的文字要在生成端断根**，排版端只能做兜底；两边都做才算稳。
- 体检必须有**量化指标**（页尾空白 pt），否则「看起来是不是满了」全靠肉眼，改完不敢确认。
- 空白大不一定是 bug：`curric-*` 系列第 2 页空 500+pt，是因为体检样本没走自动补题，
  不是分页错。得先分清「样本问题」和「排版问题」再动手。

# v0.12.0 出题偏好：题型倾向 + 卷面用途（同日）

## 起因
参考 `https://edu.zmpai.com/ai-worksheet` 的功能设计（AI 练习卷）：题型倾向 7 档、卷面用途 3 档、
一次出两张、导出图片、看图题。判断是**设计可搬、内容不能搬**（该站有 ICP 备案，题库是它的资产），
且**不接 AI 生成**（会算错、破坏离线与零成本），最终走程序化生成。
三条按顺序做：v0.12.0 倾向+用途 → v0.13.0 两张+图片 → v0.14.0 看图题。

## 做了什么
- `Models.kt`：`QuestionFamily`（选择/填空/判断/计算/应用/阅读）+ `Tilt`（7 档）+ `PaperPurpose`（3 档）；
  `QuestionType.family` 写成**集中式 when** —— 49 个题型逐一加参数容易漏，忘了归类会编译期报错。
- `PaperComposer`：`orderByTilt` 名字贴切优先（`label.contains(prefer.label)` → 2、
  `family == prefer` → 1），再 `countFor` 按用途查表（DAILY 30/10/8/8、UNIT 18/10/8/6、
  REVIEW 16/10/8/6）并按答题线数封顶（≥3 条线 → 8 题、2 条 → 10、1 条 → 16）。
- `AppState`：`tilt` / `purpose` 两个状态 + `applyPreference` + `canUseTilt` + `normalizeTilt`。
- `Screens`：新增「02 出题偏好」卡片（在「01 自由组合」和「03 题型库」之间），
  七个倾向 chip 用 `FlowRow` 折行，不可用的置灰。

## 三个真问题（都是 dumpRatios 看出来的，肉眼点不出来）
1. **科学科目把两个新参数整个吞了**。`defaultSpec` 里科学分支写死 `8/10/8`，
   7 档倾向 × 3 档用途 = 21 种组合，配比一个数字都不动。改成 `scienceCounts()`：
   倾向决定主型、用途决定铺多宽（日常 20 / 单元 28 / 复习 32，题库每级每型 12 道上限）。
2. **「假控件」**：数学没有判断题、语文没有计算题，点了倾向配比不变却照样显示已选中。
   加 `PaperComposer.fits()` + chip 置灰 + 一行说明「当前科目没有【判断题、阅读理解】这类题」；
   换年级/科目导致倾向落空时 `normalizeTilt()` 自动回落均衡搭配。
   —— 这跟 v0.11.2 那个「columns 声明了从没被读」是**同一类病：控件点了有反应，但反应是假的**。
3. **单元检测配比失衡**（20+4+4）。`countFor` 前期按 `answerLines > 0` 一刀切给 4 道，
   改成按用途查表 + 按答题线封顶。

## 新增工具
`DebugSheetDump.dumpRatios`（`am start --ez dumpRatios true`）：倾向×用途×年级×科目
全组合只打题型与题量，几秒跑完 40+ 组。**手点 21 种组合看不出「切了等于没切」这种静默失败**。

## 实测
| 场景 | 结果 |
|---|---|
| 三年级数学 · 单元检测 | 34 题 / 3 页：口算 18、竖式 8、脱式 8 |
| 三年级数学 · 计算解答偏多 + 单元检测 | 26 题 / 3 页：竖式 8、脱式 10、口算 8 |
| 三年级数学 · 判断题偏多 | chip 置灰 + 「当前科目没有【判断题、阅读理解】」 |
| 一年级数学+科学 · 判断题偏多 | 科学判断 6 → 10，说明只剩「阅读理解」置灰 |
| 去掉科学后 | 倾向自动回落「均衡搭配」，说明恢复两项，配比回到 18/8/8 |
| release 端到端 | 26 题 → 自动补 1 题 → 27 题 / 3 页 / 末页 90% |

## 教训
- **枚举参数加完要查「谁读了它」**。`tilt`/`purpose` 加进 `PaperSpec` 不等于生效，
  科学分支和 `countFor` 都会悄悄忽略它。加完立刻写 dump 把组合全打出来。
- **控件不能假装有反应**。做不到的组合就置灰 + 说清原因，比「点了没变化」诚实得多。
- 置灰不可怕，可怕的是**换科目后倾向静默落空** —— 必须配套 `normalizeTilt()` 回落，
  否则 chip 会一直显示已选中、配比却是别的。

# v0.13.0 一次出两张（A/B 卷）+ 每页导出 PNG（同日）

## A/B 卷
参数页「生成张数」1 张 / 2 张。核心决定：**B 卷沿用 A 卷自动补满后的题量，只换种子**
（`COPY_SEED_STEP = 7919L` 质数偏移）。让 B 卷自己再补一轮，两张卷的大题题数很容易对不上，
批改时没法对号，A/B 卷就退化成两份不同的卷子。卷头直接印「A 卷 / B 卷」。
两张都 `savePaper` 进试卷库，`Built` 各自带 `savedId`，切卷后标错题关联不会串。

`applyBuilt(b, clearBatch = true)`：打开历史卷 / 错题卷 / 每日一练都会走它，
不清批的话预览页会**残留上一批的 A/B 切换**，点下去跳到一个毫不相干的卷子。
只有 `generate()` 和 A/B 互切传 `clearBatch = false`。

## 导出图片
每页一张 PNG，`EXPORT_IMAGE_SCALE = 2.2f`（≈1309×1852）。预览用的是 1.5，
但导出要落到纸上 —— 拿预览那张 892px 宽的图打印，字会发虚。
落地在 `papers/images/`（FileProvider 已覆盖 `papers/` 子树，不用改 file_paths.xml）。
分享走 `ACTION_SEND_MULTIPLE` + `ArrayList<Uri>`：微信只接受一次多图，
逐张 `ACTION_SEND` 会连弹三次选择器。

## 实测
| 项 | 结果 |
|---|---|
| 2 张生成 | 52 题 / 2 页，卷头「数学练习　A 卷」，toast「已出 A / B 两张」 |
| 切 B 卷 | 题量同样 52、结构同样只有「一、口算」，题目全不同（A:197÷96 → B:443÷367） |
| 导出图片 | 2 个 PNG，239KB / 141KB，1309×1852，文件名带「B 卷_第1页」 |
| release 包 | versionCode 21 / 0.13.0 装上，首页正常 |

## 教训
- **"生成两张"不能是"跑两遍生成"**。A/B 卷的价值在结构可比，所以共享题量与结构、只换题目。
  凡是"再跑一遍"，都要先问一句：两遍的结果还需不需要互相对得上。
- 分享多文件注意 intent 类型：`ACTION_SEND_MULTIPLE` + `ArrayList<Uri>` + `image/png`，
  三者缺一个在部分 App 上就静默没反应。
