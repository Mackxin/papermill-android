# 2026-11-16 · PaperMill v0.17.0 卷面定制

用户五条需求（配两张截图）：卷子显示生成时间、底部页脚可自定义、姓名班级日期得分可后台隐藏、
标题与「共 N 题 满分 M 分」显示成一行、放大后多页可左右切换、行距可后台自定义
（原话：**「我要的是充分利用纸张，不要有太多的空白了」**）。

## 五个开关（都在「卷面设置」里）

1. **页脚三态** —— 不是「留空 = 不印」：留空分不清「懒得写」还是「不要页脚」，两者差 26pt 纸面高度。
   用 `footerMode: 0 默认 / 1 自定义 / 2 不印`。页脚文字靠左、生成时间靠右（以前整句居中，
   一旦允许自定义长句必然和时间叠），两样都空时**连分隔线都不画**，正文多吃 26pt。
2. **生成时间** —— 印在页脚右侧，可单独关；页脚整条关掉时它也一起关（「不印」的意图是纸尾干净，
   只在右下角留个时间戳不叫不印）。
3. **姓名 / 班级 / 日期 / 得分整行隐藏** —— 省 26pt。孩子在家做练习卷时这四栏本来就没人填。
4. **标题排版：两行 / 一行** —— `subtitleInline`，省 17pt。一行时标题+副标题当一组居中
   （只居中标题会让副标题伸出右边界），副标题与标题同基线。
5. **题间行距三档**（紧凑 / 标准 / 宽松）—— `LineGap(base, max)` 两个数而不是一个系数。

## 行距撑开算法重做（本版最大的坑）

原来是「从 base 到 max 取 4 档，一超页就停在上一档」。实测 52 道口算占 3 栏 18 行，
四档只到 13pt，**填充率停在 83%，纸尾空 110pt** —— 等差数列档位太粗，10pt 跳到 13pt 就多一页，
中间那一截全浪费。

改成「不增页」前提下**二分试排** 6 次（误差 <0.5pt），`LineGap.max` 也从 13~20 抬到 26~34。

但第一版二分反而把两页的卷子弄糟了：`chart-g3` 从 5/536/527 变成 113/377/527 ——
题从「第 1 页塞满」变成「第 1 页空 113pt」。原因：**评分只看末页填充率**，
页数没变、末页分数没变就照收。改成按**最差那一页**的填充率评分
（`worstFillOf`），等于要求「拉间距不许把任何一页弄得更空」。

实测页尾空白（`dumpPaper`）：
| 样本 | 改前 | 改后 |
|---|---|---|
| oral52-g3（52 口算） | 64 / 5 | **11 / 5** |
| curric-math4 | 0 / 345 / 5 | **11 / 34 / 5** |
| curric-chinese6 | 0 / 403 / 0 | **0 / 219 / 47** |
| head-oneline | 81 / 5 | **12 / 5** |
| no-footer | 63 / 19 | **0 / 19** |
| all-tight（一行+紧凑+无姓名行+无页脚） | 21 / 19 | **0 / 19** |

## 放大浮层多页切换

v0.14.0 的浮层只看得到当前那页，想看下一页要退出 → 滑动 → 再点进来。
现在 `PageZoomDialog(pages, initialPage, onDismiss)` + `HorizontalPager`：
横滑翻页、两侧箭头（黑屏上横滑不是每个人都想得到）、底部「第 N / M 页」+ 操作提示。
翻页后缩放倍数归 1（否则新一页从 3 倍开始，看到一块模糊的纸角，以为印坏了）。

**手势分工是唯一难点**：
- 1× 时单指横滑 = 翻页（交给 pager，我们不碰）
- 双指 = 缩放（自己吃掉事件，pager 的拖拽被取消）
- 放大后单指拖动 = 平移（此时 pager `userScrollEnabled = false`）
用 `transformable` 会连单指拖拽一起吃掉、翻页永远滑不动，所以手写了一个
「只在双指 / 已放大时才消费事件」的 `awaitEachGesture`。

## 三个自挖的坑

1. **箭头白底白字隐形** —— `Color.White.copy(alpha=0.14f)` 的圆底 + 白箭头，正好压在白色 A4 纸上，
   截图里完全看不见。改深色半透明圆底（黑 42%）+ 白字。
2. **「点任意处退出」吃掉 down 事件** —— 挂最外层 Box 时，它在按下那一刻就消费 down，
   pager 的滚动手势收不到起点，**横滑翻页整个失灵**（`input swipe` 滑了没反应、页码不变）。
   改挂到页内图片上（等于预览缩略图那套「页内可点 + 外层可滑」）。
3. **页脚选「不印」但右侧时间还单独印** —— `hasFooter = footerText非空 || stamp非空`，
   于是「不印文字 + 印时间」= 只印时间。改成 `footerText == ""` 时 stamp 也置空。

顺带修 v0.17.0 之前的隐患：`updateDockGlass` 每次只存 `dockGlass`，
`AppSettings(...)` 其余字段回默认值 —— 用户改页脚、顺手切一下 dock 玻璃，页脚就悄悄变回去。
统一走 `AppState.saveSettings()` 单一出口。

## 遗留（未修，下一版查）

`vertical-g4` 9 道竖式 2 页、页尾空白 **237/435**；`scramble-g4` 15 道单词拼装 **380/295**。
这两条路径本版没动过（`QuestionBlock` 无图时 measure/paint 一行没变），
是「一屏放不下整行题块 → 最后一行整块掉到下一页」的老毛病。占位题多栏/整行的取整策略要单独查。

## 发版

commit `7119030` → push → release v0.17.0「卷面定制」+ `papermill-v0.17.0.apk`（17250677 B）。
验证：编译通过 → 装机 → `dumpPaper` 17 个样本 → UI 逐项点验（一行标题 / 隐藏姓名行 /
页脚不印 / 紧凑档 / 箭头翻页 / 横滑翻页 / 点任意处退出，均实测通过）。

# PaperMill v0.17.1 · 流畅度 + 排版留白

用户：「修掉（vertical-g4 / scramble-g4 的空白），还有现在 APP 有点卡顿，
点击从第一个 Tab 跳到第三个 Tab 中间会闪、还会卡顿，流畅度需要优化。」

## 一、切 Tab 闪 + 卡

根因两条，都在 `MainUi` 的 pager 联动：
1. `animateScrollToPage` 一律用动画 → 从首页点「错题本」时，**中间那页被整页拖着过屏**，
   看起来就是「闪」。
2. `beyondBoundsPageCount = 1` 让三页同场，那 240ms 里中间页要现场组合、
   几十张带阴影的卡片要逐个栅格化 → 必然掉帧。

改：**跨页瞬切（`scrollToPage`）、相邻页仍滑动**（`abs(idx-current) <= 1`）。
实测「测量布局」高峰 **2289ms → 0.9ms**，每次切 tab 渲染帧数 35 → 5。

## 二、卡顿（其余）

- `persistSession` 原来在**主线程**序列化 + 写 JSON（滚停 1.2 秒后正好卡在手指离屏那刻）。
  改：主线程只取快照，写盘进 `ioScope`（SupervisorJob + IO）。
- 记住滚动位置的 `snapshotFlow` 用 `intArrayOf` 打包 —— 数组没有结构相等，
  `distinctUntilChanged` 形同虚设，静止时还在空转。改 `Triple` + distinctUntilChanged。
- 列表补 key：错题按 `m.id`、纸张网格按 `keyPrefix-row-N`
  （同一 LazyColumn 里 sheetRows 被调十几次，不给前缀 key 会直接重复崩溃）。
  没 key 时切换筛选按位置比对，整屏重组重绘。
- `CardSection` 去掉重复的 `.clip()`：`shadow(elevation>0)` 默认已裁剪，再来一层等于多建离屏层。

## 三、最关键的一刀：发版改用 release 包

之前五个版本发给用户的都是 **debug APK**（17MB、dex 未优化、带调试检查）。
这次 `isMinifyEnabled = true` + `isShrinkResources = true` + 自写 `proguard-rules.pro`：
- 包体 **17MB → 1.9MB**（-89%）
- 冷启动 **4.6s → 1.85s**（-60%）
R8 风险点核查过：无反射、无 Gson/Retrofit 注解解析、无 JS 桥，只 keep 了 MainActivity。
装 release 后全链路验证：出卷 / 预览 / 放大浮层 / 打印纸列表 / 速查表出 PDF，全部正常。

⚠️ 教训：**发版前先问「这次发的是 debug 还是 release」**。用户装的是 debug 包，
所有性能反馈都要按 debug 包的基线来算。

## 四、排版两处老账

| 样本 | 改前 | 改后 |
|---|---|---|
| vertical-g4（9 道竖式） | 237pt | **33pt** |
| scramble-g4（15 道单词拼装） | 380pt | **51pt** |
| oral52-g3 | 11pt | **0pt** |
| gap-compact / gap-loose / head-oneline | 14 / 13 / 12 | **0 / 1 / 0** |

两个新能力（都在 PaperRenderer）：
1. **余量转答题线** `fillWithAnswerLines`：正文刚好一页且填充率 <90% 时，
   逐步给「本来就多线」的大题加线（最多 +3 条，不许增页）。
   **只给 answerLines >= 2 的大题加** —— 一开始无差别加，单词拼装每题被塞 3 条线，
   又浪费又让栏高错开（题干折行的题和没折的错半行，整页像拼错的）。
2. **按高度试排栏数**：只按题面宽度定栏数时，15 道短题干 → 3 栏，
   纵向只占半页。现在「正文刚好一页」时把 minCols..6 都试一遍，取填充率最高、不许增页。
   下界用题型自己声明的 `columns`（竖式 3 栏是「一道竖式要够宽」的经验值，
   试排把它压成 2 栏就是违规 —— 第一版真发生了，看图才发现）。

顺带：单词拼装答案位从「（　　）」改成一条书写横线（`answerLines` 0→1）——
一个 4~10 字母的单词挤在两个全角空格里根本写不下。改完 15 题变 2 栏、每题一条长横线，
像真实的听写纸。

用户六条反馈（配两图）：
1. 卷子左下角的文字怎么自定义（入口找不到）
2. 点某个东西会滑动还自己抖动一下

4. 错题本难搞，孩子做完哪些是错题怎么快速记录
5. 课本入口也放到 tab 栏
6. tab 栏可以后台自定义显示哪个，高度也不用那么高

## 一、关键改动

- **NavTab 变成唯一事实来源**：`enum class NavTab(val label: String, val screen: Screen)`，6 个值
  （HOME/REFERENCE/MISTAKES/HISTORY/TEXTBOOK/MORE）。删掉 `Screens.TAB_ORDER` 与
  `CommonUi.DOCK_TABS` 两份硬编码（原来靠注释「顺序必须一致」维持，一加页签就错位）。
- **页签集合动态化**：`AppState.dockTabs` + `toggleDockTab()`（三条护栏：「更多」不可关、
  至少留两个、正停在被关的页先退回「更多」）。`parseDockTabs` 兜住枚举改名/脏值/全空。
  `AppSettings.dockTabs` 存逗号分隔的枚举名。
- **pager 按页签集合重建**：`val pager = key(tabs) { rememberPagerState(...) }`，
  三个联动 effect 的 key 从 `Unit` 改成 `pager`。
- **dock 压矮**：胶囊 42→36dp、内外边距各收 1~2dp，`DOCK_SPACE` 70→58dp。

- **批改记错题面板**：`GradingSession` + `startGrading()/finishGrading()`，挂在根节点一份，
  预览页与试卷库共用。题号格子点选 + 「3 7 12-15」文本解析
  （空格/逗号/顿号/分号/换行都收，区间认 `- ~ ～ － —`）。
- **试卷库三个动作**：打开（reopen）/ 改参数（新增 `editSaved`）/ 批改（不重渲染，用题目快照）。
- **页脚入口提到「实时预览」正下方**：独立「页脚那行字」卡片，输入即切到「我写的」；
  卷面设置里那份重复控件删掉。
- 修 ChoiceChip / DockItem 字重导致的宽度跳动：正文 + 透明「加粗版」叠两层，
  透明层参与测量 → 宽度与选中态解耦。
- 修提示条顶动底部按钮：`ToastBar` 从操作条那个 Column 里挪出来，独立 Box 浮层
  （`STICKY_BAR_SCREENS` 判断要不要让出操作条高度）。
- 错题卡题型不再印枚举名（`ORAL` → `口算`）。
- LocalStore：`addMistakes` 抽出 `addMistakesCore`，新增 `addMistakesFromSaved` /
  `addMistakesForPaper`（三道入口共用一套去重逻辑）。

## 二、踩到并修掉的坑

1. **关掉一个页签后顶栏标题与内容错位** —— 页码 5 越界回弹到 4，回弹途中 settledPage 报出 3，
   `tabs[3]` 是「课本」→ `goTab(TEXTBOOK)`，而 pager 停在「更多」那页。
   根因是页码与页面在两个状态下各自漂移。解法：`key(tabs)` 重建 pager，
   初始页取「当前页面在新集合里的位置」，页码从出生就一致。
2. **改参数后标题印成「…数学练习　A 卷　A 卷」** —— 试卷库存的标题已含 A/B 卷后缀，
   再走 `currentSpec` 又拼一次。加 `stripCopyLabel()` 只剥后缀；
   分隔符是全角空格 `\u3000`。
3. **`@Composable` 注解残留** —— 替换 `HistoryScreen` 时把原来的 `@Composable` 留在 KDoc 上方，
   `LazyListScope.historyScreenItems` 编译报「@Composable invocations can only happen
   from the context of a @Composable function」。
4. **`reopen` 用 `defaultSpec` 的 counts** —— 拿历史卷当模板会「题量和纸上印的不是一回事」。
   `editSaved` 必须从 `saved.counts` 读回来（实测 ORAL=30 → 30 题）。
5. **模拟器 tap 偶发不生效**，排查必须先 `uiautomator dump` 拿真实 bounds。
   我因为看错「课本 / 试卷库」两格的位置，误判过一次「点了没反应」，
   还误以为是 `toggleDockTab` 的 bug。

## v0.18.1 行距收窄 + 每页印页码 + 页脚高度可调（2026-11-16 17:10）

用户原话：「生成的卷子行与行之间间距不要那么宽，再窄一点，或者后台可以自定义，
每页纸都要有显示时间和页数，高度可以自定义」。拆成四件事，全部落地并发版
（commit `64450b5`，Release `v0.18.1`，APK 2021553 B / versionCode 28）。

### 行距为什么宽 —— 不是默认值的问题，是算法
`stretchGap` 在「不增页」前提下二分把题间距拉到 `LineGap.max`。原来 max 是
26~34pt，等于题与题之间能拉开一个半行。只调 `base` 没用，**必须压 max**。
改成 5/9/15/26，默认档 NORMAL → COMPACT。

`LineGap.CUSTOM` 的语义是「不撑开」：`gapBase == gapMax == lineGapCustom`，
`stretchGap` 调用点加 `doc.gapMax > doc.gapBase` 守卫。实测 0pt 时填充率只有
72%（自动补满加了 24 题），证明剩余高度**没有**被摊到行距上 —— 这正是想要的行为。

### 页码以前只有第 2 页起有
`drawRunningHeader` 只在首页以外调用，首页没页码。改成 `drawFooter` 统一负责
`第 N/M 页`，页眉只留卷名（否则重复）。`hasFooter` 语义也跟着扩到含 `showPageNo`。

### 页脚高度是排版参数，不是外观参数
`FooterSize`（矮 20 / 标准 26 / 高 32pt，height 与 fontSize 联动）。正文可用高度
直接减掉这一截，所以 `GridPainter` / `ThemeCardPainter` 都加了 `footerH` 参数 ——
它们原来用 `g.contentBottomSafe` 写死 26pt，选「高」会把格子压到小字上。

### 题面折行的真凶：两个叠加的 bug
1. `fitColumns` 取 **80 分位**题面宽度定栏宽。单位换算 15 题里 4 道超长
   （`4米26厘米=（ ）厘米`）被漏算 → 判定 3 栏够用 → 折行。
   加 `strict` 参数：整卷统一栏数时按**最长题面**算上限。
2. `for (cols in minCols..maxOf(minCols, widthCeil))` —— 宽度天花板算出 2，
   但 `maxOf(3, 2)` 又抬回 3，**等于 strict 白算**。改成 `hi = min(MAX, widthCeil);
   lo = min(minCols, hi)`。宽度是硬约束，题型声明只是偏好。

36 题实测：3 栏折 4 处 → 2 栏零折行，页尾空白 88pt → 0pt，页数不变（仍 2 页）。

### 设置迁移（这次踩的新坑）
只改代码里 `val lineGap = LineGap.COMPACT` 对老用户**完全无效** —— 磁盘上
`settings.json` 存着 `"lineGap":"NORMAL"`，`applySettings` 读回来照样宽，
用户会以为这版没改。加 `layoutVersion`（`AppSettings` + 读写 + `LOAD_VERSION=1`）：
读到 < 1 且当前是 NORMAL 才换成 COMPACT，然后 `saveSettings()` 写回。
实测：
- 老设置 `NORMAL` + 无标记 → 重启后 `COMPACT` + `layoutVersion:1`
- 再重启一次 → 保持 COMPACT（不反复迁移）
- 手动设 `LOOSE` + 清标记 → 重启后**保持 LOOSE**，只有标记升到 1（用户意图优先）

坑点：`LocalStore` 的 settings 是**手写 JSONObject 逐字段 put/opt**，不是序列化框架。
加字段必须两边都补（`put` 漏了则永不落盘，`optInt` 漏了则每次启动都迁移）。

### 体检样本
`DebugSheetDump` 新增 `unit36-g3` / `unit36-tight`（FILL_BLANK 8 + CHAIN_CALC 6 +
TWO_DIGIT 5 + UNIT_CONVERT 17），就是用户那张卷的题型组合。以后动排版先跑它。

## v0.18.2 应用题两栏 + 答题线封顶 + 加题可选题型（2026-11-16 17:57）

用户三条：①「这个回答不用空那么多行」②「这个可以一行两列排版」③「生成的卷子
可以自定义删减添加」，配图是同一张应用题卷（5 题占满整页、每题 4 条横线）。
发版 commit `4f5a11b`，Release `v0.18.2`，APK 2023877 B / versionCode 29。

### 应用题改两栏 —— 连锁踩了两个坑
`WORD_PROBLEM("应用题", 1, 4)` → `(2, 3, padWithLines = false)`。改完发现还是 1 栏：

1. `PaperComposer` 算栏是 `maxOf(type.columns, spec.columns)` —— 用户在参数页
   选 4 栏，应用题跟着变 4 栏，一行半句话。改成：`answerLines > 0` 的题型
   不跟全局栏数走，只认自己声明的值。
2. `PaperRenderer` 的「按高度试排栏数」用 **填充率** 评分：6 道应用题排 1 栏
   占 500 多 pt、排 2 栏只占 250pt，算法必然选 1 栏 —— 等于用户要的两栏被
   优化目标反着否掉。改成：`answerLines > 0` 的题型不参与试排
   （`forceColumns > 0 -> if (answerLines > 0) section.columns else forceColumns`）。

教训：**「填满纸」这个优化目标不能套在需要手写空间的题型上**。它和「一行两题」
方向相反，算法越聪明越糟糕。

### 答题线越加越多 = 「空那么多行」的真凶
`fillWithAnswerLines`（v0.17.1 为修竖式纸尾 237pt 空白加的）最多 +3 条，
应用题从 4 条被撑到 **5 条**。用户抱怨的"空行"正是它。

先试过「封顶 4 条」（MAX_ANSWER_LINES），结果竖式从 33pt 空白退化到 204pt
—— 竖式恰恰是靠加线填纸的。最终方案：给 `QuestionType` 加 `padWithLines`
（默认 true），应用题设 false。竖式恢复原行为，应用题固定 3 条线，宁可留白。

又一次印证：**同一个"填满"策略不能对所有题型一刀切**，得让题型自己声明。

### 加题可选题型
- `appendQuestion(type: QuestionType? = null)`：null = 老行为（加最后一题的题型），
  指定题型时已有该大题就并进去、没有就新起一道
- 抽 `PaperComposer.sectionOf(spec, type, questions, ordinal, instruction, prefix)`
  和 `subjectPrefixFor()`：加题与出卷共用同一套标题/分值/栏数规则
  （两处各写一遍，纸上迟早出现「共 6 分」底下排 4 道题）
- `AddQuestionDialog` 挂在根节点（不在 LazyColumn 里），状态放 `state.addingQuestion`
  —— 放 remember 里会随 item 滚出屏幕而丢
- `addableTypes()` 只列当前年级+科目真能出题的，跟参数页同一套判断

## v0.18.3 批量删题 + 指定页数（2026-11-16 21:05）

用户三条：①「题目清单的支持批量删除」②「检查一下代码还有没有需要优化的地方」
③「可以选择试卷生成几页，这样的话题目可以根据试卷自动压缩显示的内容大小」。
发版 commit `33a7863`，Release `v0.18.3`，APK 2026337 B / versionCode 30。

### 批量删题：为什么单独做一个模式
复用错题那个 checkbox 最省事，但**语义会打架**：勾选既是「这题做错了」（勾完点
加入错题本）又是「这题要删」，家长勾好错题手滑一点就没了半张卷。
所以 `state.batchSelect` 单开一个模式：进入后勾选框改语义、单题「换一题/删这题」
按钮隐藏（一行一个「删这题」会让人分不清哪条路才对）、底部换成红色「删除选中」。
`selectByExpr` 复用判分面板的 `parseNumberList`（改成 internal，别写两份）。

### 指定页数：唯一能同时守住「不删题」和「不超页」的旋钮是字号
行距已压到极限（紧凑 9pt），栏数按题面宽度定死 —— 剩下只有字号。
`targetPages` 语义是**上限**：题少就自然少页，不硬撑（硬撑只能放大字号或拉行距）。
渲染里二分 6 次找最大可行 scale，下限 `MIN_TYPE_SCALE = 0.72`
（11pt → 7.9pt，A4 中文约 2.8mm，还读得清）。

**关键取舍：压不进就多印一页**，不打肿脸充胖子。`best == null` 时保持原字号，
预览页显示「题量太多，缩到最小也塞不进 N 页，已按原字号排 M 页」。
卷头 / 页眉页脚不缩（那是骨架，缩了会出现「标题比题干小」）；答案页不参与。

`RenderedPdf.typeScale` 一路带到 UI：缩过就说「缩到 92%」。
不说的话用户只会觉得「这版字怎么变小了」，像个 bug。

### 体检才发现：targetPages 只管正文，一开始的样本全踩空
头两轮 `limit1-oral52` / `limit1-unit36` 都是 1.00 不变色 —— 因为这两卷**正文就是
1 页**，另 1 页是答案页。改成 80 题口算 / 36 题×2 才真的触发。
教训：写样本前先想清楚「我要验的那条路，前置条件到底成不成立」。

三条路都验住了：
| 样本 | 正文 | 缩放 |
|---|---|---|
| limit1-unit36x2 | 2 → 1 页 | 0.996 |
| limit2-vert40 | 3 → 2 页 | 0.917 |
| limit1-vert40 | 3 → 3 页（压不进）| 1.000 |

### 顺带修的四个「印出来对不上账」
1. 删题后标题「共 N 分」不重算 → 抽 `PaperComposer.sectionTitle`，
   删题走 `rebuildSections`（同时重编序号、剔除删空的大题）
2. 删空的大题留下孤儿段，序号从「一」跳「三」→ 同上
3. 卷头印「…A 卷　A 卷」→ `currentSpec` 只在 `copySuffix` 非空时 `stripCopyLabel`
   （单张卷模式下用户自己写的「A 卷」要保留）
4. 删题后错题勾选错位（题号整体重排）→ `commitRemoval` 末尾清空 `wrongNumbers`。
   留着比清掉危险：用户点「加入错题本」，进错题本的是另一道题。

### 代码体检（用户问「还有没有要优化的」）—— 留给下一版
- `PaperSpec.fontSize` 是**死字段**：到处赋值 11f，渲染层写死 `BODY_SIZE = 11f`，
  从没被读。要么删，要么真正接上（现在是三处各写一个 11f）
- `bodyFillOf` 只看**最后一页**：多页卷首页空了也不会触发撑开。
  正解是判定用 `worstFillOf`（stretchGap 内部评分已经在用它），
  但 v0.18.1 刚把行距压窄，贸然改会把一批卷的行距又拉宽，等用户反馈再动
- `PaperRenderer.render()` 已 600+ 行，五个试排策略（速查表铺满 / 页数压缩 /
  挑栏数 / 加答题线 / 撑行距）串在一个函数里，局部变量互相影响，建议按阶段拆文件
- 看图题分页边界：`chart-g3` / `figure-g1` / `clock-g2` 第 2、3 页仍大面积空白
  （v0.18.1 就记下的老账，与行距无关）
- `renumber` 与 `rebuildSections` 职责重叠（前者只对 appendQuestion 有效）
